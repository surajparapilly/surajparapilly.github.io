How do the LLMs understand what I am saying?

Suraj  ·  September 2026

I've been trying to understand what is actually happening inside a GPT. I want to try my best to build this intuition from first principles. Really try to understand how it is able to understand the words that we type in, the words it consumes and so on.

The sentence I'll use throughout is:

"The cat is on the mat and it seems very hungry."

How do we get the text to something machines understand?

We have all heard that computers don't see words, they see numbers. That is true for language models as well.

So the first problem is simple:

How do we turn text into numbers?

One way would be to give every character in our corpus a unique number. For example, we could say:

a → 0 b → 1 c → 2 and so on.

So our sentence here:

"The cat is on the mat and it seems very hungry."

can be represented as a sequence of numbers.

In production GPTs, this process is called tokenization. Instead of necessarily treating every character as a token, the tokenizer breaks text into pieces called tokens. A token might be a whole word, part of a word, punctuation, or other common sequence of characters.

For example, "problematic" might be split into something like:

problem + atic

There are reasons for why a word is split as such, which I will not get to in this piece. For the purposes of building a foundational understanding, let's simplify things and assume that every word is a token. This means every word gets an ID. Just like how we give each student in a class an ID, we are doing the same thing for our text.

The important thing to understand is that the ID itself doesn't carry meaning.

If cat is 0 and is is 1, there is nothing inherently meaningful about the numbers 0 and 1. They are simply labels that allow us to identify the tokens.

So we have solved our first problem.

Text → Token IDs. Computers now can read these words as numbers

But these IDs are not yet particularly useful to “understand” all of the internet or any of the internet for that matter.

How do we encode the meaning?

Let's say we have the following token IDs:

[18, 47, 56, 57, 58, 1, 15, 47, 58, ...]

These numbers tell us which tokens we are looking at, but we need to represent these tokens in a way so that we can capture the “meaning” of it. This is where embeddings come in.

We can think of the embedding as giving the model a multidimensional space in which it can learn different ways to represent the token. Imagine you have a student in your class and to truly understand him, there are many dimensions of him that you may need to know. His english scores, math scores, how he is in class, how he is around others, family history, etc etc. The same way we use these embeddings to learn “representations” of the token. We should be careful about saying that each individual dimension represents a specific feature. The meaning is encoded in the combination of dimensions rather than one dimension corresponding neatly to one human-interpretable feature.

So, Instead of representing every token with a single integer, we map every token ID to a vector of numbers.

For our GPT, let's say the embedding dimension is 512.

So instead of just:

cat → 42

we might have:

Token → Token ID → Embedding cat → 42 → [0.12, -0.37, 0.81, ..., 0.04]

with 512 numbers in total.

A very natural question I had was where did the numbers for the embedding even come from?

These embeddings start out randomly and instead are learnt through training. So what that means is, the “embeddings” which for a basic understanding that encode the meaning of the word in the sequence starts out randomly. So although this infrastructure is set up, the meanings of these words are all random and then we learn the meanings

So now our sentence:

"The cat is on the mat and it seems very hungry."

is no longer a sequence of arbitrary token IDs. It is a sequence of 512-dimensional vectors.

But we have another problem.

Where is the position?

Consider these two sentences:

"The man bit a dog."
and
"The dog bit a man."

They contain the same tokens. The difference is their order.

If we simply looked at the token embeddings, "man" would have the same embedding in both sentences and "dog" would have the same embedding in both sentences. Both sentences would have the same set of embeddings although their meanings are different. So position also plays a key role in understanding meaning. But their positions are different, and that position matters. So the model needs some way of knowing not just what a token is, but where it occurs in the sequence. We can do this by adding a position embedding. There is an embedding vector for each position in the sequence. So for the first token, we have its token embedding and its position embedding and for the second token, we have its token embedding and its position embedding and so on.

These are added together. So the representation entering the next part of the model contains information about both the token and its position.

For our sentence:

"The cat is on the mat and it seems very hungry."

the token "it" is not just represented as "it." It is represented as "it" occurring at a particular position in this particular sequence. At this point, we have something much more useful, every token has a 512-dimensional representation that contains information about the token and its position. But there is still a fundamental problem.

How does one token know anything about the other tokens around it?

Consider our sentence again:

"The cat is on the mat and it seems very hungry."

When we get to the word "it", how do we know what "it" refers to? If we looked at the word "it" in isolation, we wouldn't know. The information we need is elsewhere in the sentence. As humans, we naturally look at the surrounding words and determine which ones are relevant. We know this because we have seen so many sentences, heard them and understood the relationships between words in a sentence to be able to infer its meaning.

A GPT also needs a mechanism for doing something similar. We need a way for the representation of one token to gather information from other tokens.

So the question is:

How do we let tokens influence the meaning of the tokens around it?

Let's imagine every token is a student in a classroom.

Each student has information about themselves, but they are also allowed to look around the room and decide who might have useful information for them.

To do this, we give each student three different representations:

Q
Query

What information am I looking for?

K
Key

What kind of information do I have?

V
Value

What information do I actually provide?

These are called Query, Key and Value, or Q, K and V.

But where do they come from? We take the token embedding we already have and multiply them by three different weight matrices. Once again, a natural question is where do these Weight matrices come from. Just like embeddings, random at first and learnt through training.

Let's say X is a matrix of all the embeddings of a sentence. W_Q, W_K, W_V are weight matrices for Query, Key and Value.

What is the significance of these weight matrices?

They are how we project the embedding - which is the meaning of the word into the 3 representations, Query, Key and Value we mentioned previously.

One for Query:

Q = X*W_Q

One for Key:

K = X*W_K

And one for Value:

V = X*W_V

So our sentence:

"The cat is on the mat and it seems very hungry."

now produces three matrices. One containing the Queries, one containing the Key and one containing the Values. Every token now has its own Query, Key and Value representation.

Now that we have Query, Key, Value set up, the next question is:

How do we inform each token of the others in the sequence?

This is where we compare Queries and Keys. We take the Query matrix and multiply it by the transpose of the Key matrix:

Q*Kᵀ

This gives us a matrix of attention scores. Essentially what that means is, every row in the matrix represents a token asking:

"How relevant is every other token to me?"

And every column represents a token's Key being evaluated by the Queries of the other tokens.

For example, when we look at the row corresponding to "it", we can see how strongly the Query for "it" matches the Key of every other token.

A high score means:

"The information represented by this token's Key looks relevant to what I am looking for."

A low score means:

"This token probably isn't very relevant to me."

The model has now created a map of relationships between tokens.

But there is an important problem. The model cannot see the future

Remember what a GPT is fundamentally trying to do. It is trying to predict the next token.

If the model is trying to predict what comes after: "The cat is on the mat and" it cannot be allowed to look ahead and see: "it seems very hungry."

That would give the model the answer before it has predicted it. So we apply what is called a causal mask. The mask prevents every token from attending to tokens that come after it.

Conceptually, our attention matrix looks something like this:

Everything above the diagonal is blocked.

This means "it" can look at "cat", but "cat" cannot look at "it".

The model is therefore forced to reason using only the information that would actually have been available at that point in the sequence.

Moreover, look at the row for “it”. The model compares the Query of “it” against the Keys of all the tokens that came before it. In this example, the score between “it” and “cat” is 1.80, while the score between “it” and “mat” is 1.25. This means that, at this point, the model considers “cat” more relevant to “it” than “mat”.

We want to turn them into weights that tell us how much information to take from each token. First, we scale the scores by the square root of the dimension of the attention head.*

How do we know proportionally how much to apply these weights to each token’s embeddings?

We do that by applying softmax. For simplicity let’s assume this is a normalizer, it forces all the values to be between 0 and 1.

Softmax converts the scores into a probability-like distribution where the values in each row sum to 1.

For example, if the token "it" considers the previous tokens and produces scores that become the ones highlighted in yellow.

The model is effectively saying:

"Of the information available to me, these are the relative amounts I want to take from each token."

And now we finally have something that deserves to be called attention.

The model has taken the question: "What information is relevant to me?" compared it against the Keys of the other tokens, applied the causal constraint, and converted the resulting scores into weights.

The final step is to use those weights to take a weighted sum of the Value vectors.

In other words:

Attention weights × Values

This gives each token a new representation containing information gathered from the tokens it considered relevant.

So the representation of "it" can now contain information gathered from earlier tokens, including "cat". The token started with information about itself. Through attention, it can now incorporate information about the tokens around it.

And that is the fundamental idea.

We started with:

Text —> Token IDs —> Token embeddings —> Position embeddings —> Queries, Keys and Values —> Attention scores —-> Weighted information from other tokens

We started with a sentence that was just text:

"The cat is on the mat and it seems very hungry."

And we have now reached the mechanism that allows one token to look at the tokens that came before it and determine which ones are relevant.

This is self-attention. One thing about this piece is that I have glossed over the part of “learned matrices”. Embeddings were random, Weight matrices were random and after all that they all somehow “Learn” give us the ability to understand different things. I would likely write the following piece to be able to give an intuitive understanding of what this “Learning” and “Learned matrices” are all about.

* The dot product is a sum across all the dimensions of the Query and Key vectors. As the dimensionality increases, these scores tend to become larger. Since we apply softmax immediately afterwards, very large scores can cause softmax to become extremely concentrated on one token. Dividing by √d_k keeps the scores at a more manageable scale and helps maintain useful gradients during training.
